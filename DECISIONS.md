# DECISIONS

Choices made where the spec (v1.2, 14 Oct 2026) was ambiguous or could not be followed literally.
Rule 6 (freeze line): after the first real session, every change is logged here with time and `APP_VERSION`.

## Build decisions (before the freeze line)

### LLM
0. **Provider: Mistral AI** (decided by the researcher, 14 Oct 2026). It is used through the spec's `openai_compatible` adapter (`LLM_BASE_URL=https://api.mistral.ai/v1`), which sends the spec 3.3 temperature and max tokens unchanged. `LLM_JSON_MODE=true` adds `response_format: {"type": "json_object"}`, which Mistral supports on all models, to cut down invalid-JSON retries. Models must be pinned to dated ids, never `-latest` (`npm run llm:models` lists them). HTTP 429 (rate limit) is treated like any other failed call (rule 10), so the account's rate limit must cover about 30 parallel learners; check it with the load test (step 7 in the README). The Anthropic notes below apply only if the provider is switched back.
0b. **Model: `mistral-medium-2604` (Mistral Medium 3.5) for grading and tutoring** (14 Oct 2026, after enabling API pay-as-you-go; new key). Smoke test v1 on the same 192 items: Medium 95% exact agreement, 100% same correct/incorrect side, all 6 injections flagged and scored 0. Mistral Small 4: 91% exact, but it scored 2 injections as 3, so it fails. Ministral 14B: 87% exact, injections passed, but in live tests it wrote faulty Romanian ("Ai gândit la"), gave away answers in hints and solved the learner's own question in a worked example (rule-breaking for the hint/example comparison), and produced invalid JSON 7 times in one 12-learner run. Ministral 8B scored the JSON injection as 3. Medium is also faster (tutor 1.0–1.9 s). Limit on this account: 2000 requests/min. Cost about $0.05 per learner (measured: ~16k input + ~3k output tokens per session at $1.50 / $7.50 per million tokens, third-party price listing). Earlier choice (superseded): `ministral-14b-2512` on the free API tier, which had 0 requests/min for Small and Medium.

1. **Sampling parameters depend on the model (Anthropic adapter only).** Current Claude models reject `temperature` (HTTP 400): Opus 5.5 / 5 / 4.8 / 4.7, Fable, and Sonnet 5.5 for non-default values. The Anthropic adapter (`lib/llm/anthropic.ts`) therefore sends:
   - Haiku 4.5 and the 4.6-or-older models: `temperature` exactly as in spec 3.3, no thinking.
   - Sonnet 5.5: no temperature; thinking switched off with `thinking: {type: "between_tools"}`.
   - Opus 5.x / 4.7 / 4.8 / Fable: no temperature; `effort: "low"`; `max_tokens` raised to at least 4000, because thinking cannot be disabled on Opus 5.5 and would otherwise use up the 300-token grader budget and cut the JSON off.
   The parameters actually sent are logged in `llm_calls.request.sent_params`. The `openai_compatible` adapter always sends the spec values.
   **Consequence for the researcher:** grading at temperature 0 (spec 3.3) is only possible with Haiku 4.5 (or older models). Pick the models with this in mind before running the smoke test.
2. **No server-side model fallback on refusals.** A fallback would silently switch to another model during the study. A refusal, or output cut off at `max_tokens`, counts as a failed call and goes through the normal fallbacks (rule 10).
3. **JSON parsing** accepts a bare JSON object or one wrapped in a code fence or short prose. A reply that is not valid JSON *or* does not match the zod schema counts as `invalid_json` and is retried once with the spec line. Timeouts and HTTP errors are **not** retried: the learner flow has its own fallback, and a second wait would block the learner.
4. **Time budget.** A JSON retry or leak regeneration is skipped when it could not finish within about 27 s of the request start (the route limit is `maxDuration = 30`). The tutor text is then delivered as it is, with `leak_suspected` when relevant.
5. **Name reaction** sends the spec 10.3 prompt as the user message, with no system prompt. The resulting `llm_calls` row gets its `session_id` when the session is created.
6. Unknown misconception tags are stored as `other`; the raw value stays in `llm_calls.parsed` (spec 7.4).

### Schema (`supabase/migrations/0001_init.sql`)
7. `decisions.tutor_status` also allows **`pending`**: the decision row is written *before* the tutor call. Allocation then happens exactly once even when two requests race (rule 5). A `pending` decision older than 40 s (for example after a crash) is closed as `tutor_failed`.
8. **`finalize_retry()`** records the retry answer and reward on the decision and calls `update_bandit()` in **one transaction**. It runs only if no retry was recorded yet, so the bandit can never be updated twice for the same decision (acceptance 10).
9. `EXECUTE` on `update_bandit` and `finalize_retry` is **revoked** from `public`/`anon`/`authenticated`. Supabase exposes functions through its REST API, and RLS does not cover functions.
10. Query Q2 also returns `a.id`, so the researcher can mark an alert as reviewed.

### Learner flow
11. **Refresh vs. "Continui ca …?"** The resume question appears when the link is opened in a new tab or browser that has an unfinished session. A refresh in the same tab resumes silently (`sessionStorage.pit_active`). This satisfies both screen 1 and acceptance 2.
12. **The question text is shown again on the feedback screen**, under the feedback box, in the same place for all arms. Without it the learner cannot retry. The learner's first answer is not shown.
13. **Helpfulness rating** appears on the explanation screen for *all* arms, including `plain`. It is hidden only after a first-answer grader failure (spec 5.2). After a retry grader failure it still appears, without the result line.
14. **Survey:** the preferred-help item and the three emoji items are required; the comment is optional.
15. **Minimum loading time of 1.5 s** is enforced on the server (the feedback route waits) and in the browser, for every arm.
16. Pressing "Nu știu" also stores whatever text was in the box, with `dont_know = true`.
17. The open window is checked on every route, also in the middle of a session (spec 12). Set `STUDY_OPEN_UNTIL` with some margin after the last class.
18. `POST /api/session/start` returns the existing unfinished session of the same participant instead of creating a second one (double click or refresh).
19. `prior_session_count` counts the participant's earlier **non-test** sessions.
20. `excluded_reason`: `test` is set when the decision is created; afterwards the first reason recorded is kept.
21. "Am deja un nume" accepts only letters and digits, matched case-insensitively.
22. `N_QUESTIONS` must be 10 or 12. With other values the hard/easy alternation could not end on an easy question.

### Tooling
23. **Dev-only database driver.** `DB_DRIVER=pglite` (read in `instrumentation.ts`) replaces Supabase with an in-memory Postgres that runs the real migration and imports the seed bank. It is only for local end-to-end runs without Docker, and it refuses to start on Vercel.
24. `LLM_PROVIDER=mock` gives a mock LLM for local runs and the load test. `MOCK_LLM_FAIL=all|grade|grade_half|tutor` simulates outages (acceptance 7).
25. `npm run load-test -- --no-test` creates non-test sessions. It exists **only** to check bandit updates against the in-memory dev DB; never run it against the real study.
26. The smoke test grades each answer with the `upper` band, or `lower` for questions that are lower-only.
28. **Pre-check counts letters and digits** (spec 7.1 says "fewer than 2 letters"). Found by the Mistral smoke test: the literal rule scored the correct answers "13" (DATA-H1), "12" (DATA-H3) and "x = 12" (WRLD-H3) as 0 without grading them, which would have sent learners who answered correctly to the feedback screen. Now "13" reaches the grader, while a lone "5" or "a" is still scored 0 without an LLM call.
29. **Database calls: own connection pool, 6 s limit, one retry** (`lib/db.ts`; updated after the 12-learner load test, where 4 Supabase requests hung for more than 10 s). Idle connections are dropped after 2 s, so a connection that died while the function was suspended is not reused. Inserts into `sessions` and `llm_calls` are never retried (a duplicate row would distort the data); every other write is idempotent. Originally: database calls time out after 10 s. The first production test session had one `/api/feedback` request killed at Vercel's 30 s limit, although its LLM call took under 3 s. A hung database request is the likely cause. The feedback route also logs each phase (`{"ev":"feedback",…}`) so a repeat can be located in the Vercel logs.
30. **Markdown marks are stripped from tutor text** before it is stored in `decisions.feedback_text` and shown (spec 9.1 says "no markdown"; Ministral 14B still wrote `**bold**` and `*italic*`). Only the marks are removed, never words; the raw model output stays in `llm_calls.response_text`. Same treatment for hints and worked examples.
31. **The study link is always open** (researcher's decision, 14 Oct 2026). Spec 3.1 assumes an open window; here `STUDY_OPEN_FROM=2026-10-01` and `STUDY_OPEN_UNTIL=2099-12-31`, so learners (including those catching up at home) can use the link at any time. The window code is unchanged and can be narrowed again via the env vars.
32. **Punctul IT brand applied to the learner UI** (Manual de brand, 14 Oct 2026, before any real session). Font Muli (Google Fonts name: Mulish). Frame in brand blue `#32A3DC` around the page, with the logo in the top-left corner inside the frame. Brand blue on the logo, frame, progress bar and tints. **Buttons, links, titles and selected options use a darker shade of the same hue, `#1C74A1`**, because white on `#32A3DC` has a contrast of only 2.8:1, below the 4.5:1 minimum for text; the spec asks for high contrast for children. Success text is brand teal darkened to `#0B7F7F` (4.8:1). Orange and yellow appear only as small accents (error bar, explanation bar, TEST badge), never as text. Question (22 px) and body (18 px) sizes stay as in spec 5.2; titles use the brand scale (28 / 37 px). The hint and worked-example boxes still share one style, with only the label differing (rule 2). Player names never wrap (checked down to 320 px wide), so children copy them correctly.
33. **Short study token** (researcher's decision, 14 Oct 2026). `STUDY_TOKEN` is 3 characters instead of the spec's "random 10+ characters" (spec 3.1), so it is easy to dictate to children. Accepted risk: the link is easier to guess, so outsiders could add sessions. They cannot read any data: the database is reachable only from the server.
34. **Name reaction: more room, correct Romanian** (researcher's request after the first live test, 14 Oct 2026, before any real session). Spec 10.3 asked for one sentence of at most 15 words, with max tokens 80. Now one or two sentences of at most 30 words, max tokens 160, and an explicit instruction to use correct Romanian spelling and diacritics. Reason: Ministral 14B wrote "un supereroe" (should be "supererou") and went over the limit anyway. Prompt text changed in place under `v1`; only test sessions had used the old text. The name reaction is not part of the experiment (same for every learner, before the first question).
35. **Phone alerts when the LLM provider fails** (researcher's request, 14 Oct 2026; not in the spec, not learner-facing). After a failed LLM call (HTTP 401/402/403/429, or at least 5 failed calls within 5 minutes), the server sends an ntfy push notification to the researcher, at most once per type per 10 minutes. The new table `ops_alerts` (migration 0002) is operational only, not research data. Messages contain only error codes and counts. Adds latency only to calls that have already failed; at most 3 s, for the ntfy request.
36. **Name reaction without an LLM** (researcher's decision, 14 Oct 2026; replaces #34). The reaction after choosing a player name is drawn at random from the 8 fixed lines of spec 10.3. In tests, Ministral 14B wrote incorrect Romanian ("supereroe", "glumeță", "Bună joc") and content that does not suit children (poker, "câmpul de bătălie", points, emojis), even with a 30-word limit and an explicit instruction to write correct Romanian. The name reaction is not part of the experiment; this removes that risk entirely and one LLM call per learner. The prompt stays in `lib/prompts/names.ts` but is unused.
37. **Monthly budget alert** (researcher's request, 14 Oct 2026; not learner-facing). Mistral does not expose the remaining allowance through the API, so the app estimates its spend: tokens logged in `llm_calls` this month × `LLM_PRICE_IN_PER_M` / `LLM_PRICE_OUT_PER_M`, against `LLM_MONTHLY_BUDGET` (set to 12.75, the API allowance included in the Education plan). An ntfy alert goes out at 50%, 80% and 95%, once per threshold per month. The check runs at most every 5 minutes per server instance, after successful LLM calls (SQL function `llm_month_usage`, migration 0003). It is an estimate: calls from local scripts are not counted, and all calls are priced at the configured rate. The hard stop is the spending limit in the Mistral console; when it is reached, the outage alert (#35) fires.
38. **Data correction, 14 Oct 2026 ~15:35 UTC: researcher session reclassified as test.** The researcher tested without `?test=1` (player AriciRocket29, session 5df797d6-1a52-419f-bf70-77555db027b1), which created a real session and 3 bandit updates (arm hint: rewards 1, 0, 0). The session was marked `is_test = true`, its decisions `bandit_updated = false` and `excluded_reason = 'test'`, and its answers `rating_sample = false`. `bandit_state` was recomputed from the remaining eligible updates of real sessions (none), giving Beta(1,1) for every arm and n = 0. No real learner had used the study, so the freeze line was not reached.
39. **Pilot with real children skipped** (researcher's decision, 14 Oct 2026). Spec 18 asks for a first session with 2–3 learners using `?test=1` to confirm `N_QUESTIONS` from the session length; the researcher chose not to use up learners on it. `N_QUESTIONS` stays 12. Evidence used instead: 12-learner load tests at real-class pace and the researcher's own full session.
40. **Mistral account left as is** (researcher's decision, 14 Oct 2026). The API privacy/training setting was not changed in this setup and the previous key (…zKjO) was not revoked; the researcher considers the account settings acceptable. Parental consent is confirmed by the researcher for the families who receive the link.
27. TypeScript is pinned to 5.x for known-good compatibility with the Next.js build.
